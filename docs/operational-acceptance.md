# **Aceitação operacional**

Este roteiro verifica o comportamento das instruções do holydot com o dot já existente. Ele não pressupõe servidor, runtime ou avaliador automatizado de host. Registre o resultado de cada caso como aprovado, reprovado, bloqueado ou não executado; não apresente evidência simulada como observação do host.

## **Tipos de evidência**

- **Texto/contrato:** revisão do texto público e comparação com o comportamento especificado.
- **Mock:** cenário simulado, útil para validar decisões e respostas, sem provar integração ou execução no host.
- **Chamada real ao host / leitura externa:** ação ou consulta efetivamente feita no host ou serviço, acompanhada de readback identificável. Registre o que foi observado; não alegue automação que não ocorreu.

## **Registro**

Para cada linha, anote cenário, resultado, tipo de evidência, observação verificável e limitação. “Não executado” e “bloqueado” não são aprovação. Evidência de texto, contrato ou mock sustenta somente o que foi inspecionado ou simulado; alegações sobre estado externo exigem chamada real e readback correspondente.
